    \section{Introduction}
	\textit{AccuPatt} is a desktop application created to process spray pattern data for agricultural aircraft. This includes measuring tracer dye deposition on string collectors and/or measuring droplet deposition from spray cards. The goals of this application are twofold:
    \begin{itemize}
        \item Maximize flexibility through parameterization to provide broad utility
        \item Wherever possible, simplify; The best tools don't need user manuals (And yet here we are)
    \end{itemize}
    \subsection{Measuring Deposition with String}
    The use of string for assessing aircraft spray patterns is a longstanding methodology. As a small, continuous collector, it offers both high collection efficiency for smaller droplets and high spatial resolution across a swath. The tradeoffs include a lower collection efficiency for larger droplets and its limit to measuring only relative deposition.\par
    By using a fluorescent tracer dye in the spray solution, the relative deposition along the string can be measured by exciting the dye with a light source of the appropriate wavelength and measuring the intensity of emitted light at another wavelength.\par
    This method is particularly useful for rapidly assessing pattern shape and uniformity, but it lacks the ability to provide quantifiable deposition data. It also offers no insight into droplet size distribution.

    \subsection{Measuring Deposition with Spray Cards}
    Spray cards (or paper) are another method for assessing aircraft spray patterns. By capturing droplet stains on a flat surface, they can be scanned and processed to provide quantifiable deposition data as well as insight into droplet size distribution. The tradeoffs include lower spatial resolution across the swath (unless continuous paper is used) and lower collection efficiency for smaller droplets.\par
    Spray cards can be used as a standalone method for assessing spray patterns, but they are often used in conjunction with string to provide a more complete picture of the pattern. For example, string can be used to rapidly assess pattern shape and uniformity while spray cards can be used to provide quantifiable deposition data and insight into droplet size distribution.\par
    There are three basic types of paper typically used for pattern testing:
    \begin{itemize}
        \item Water-Sensitive Paper (WSP) is a discrete sampler that changes color when it comes into contact with water; this allows it to be used without the need for a dye in the spray solution. 
        \item Cast-Coat Paper (Kromekote, etc.) is a discrete sampler that has a uniform, glossy finish which permits acquisition of smaller stains than WSP when scanned at higher resolutions. However, it requires the use of a dye in the spray solution for the stains to be visible.
        \item Bond Paper (Receipt Paper, etc.) is a continuous sampler (available in rolls) that can be deployed rapidly. It also requires the use of a dye in the spray solution for the stains to be visible. 
    \end{itemize}
    The major caveat to all spray card/paper analysis is that, while droplet density and relative coverage can be measured, the translation of stain size to droplet size is not straightforward. This is because the stain size is a function of both the droplet size and the spread factor, which is influenced by various factors such as spray solution properties, humidity, and paper properties. Therefore, while spray card analysis can provide insight into droplet size distribution, it should be interpreted with extreme caution and an understanding of its limitations.

    \section{Compatible Hardware}

    \subsection{String Hardware}
    \textit{AccuPatt} was designed around the \textit{WRK of Oklahoma} String Spectrometer System, and thus is fully compatible with that system. It uses a combination wavelength-specific LED and Band-Pass filter as the excitation source and a commercial USB Spectrometer (Ocean Optics, USB2000+, Flame or similar) as the emission wavelength measurement device. It utilizes a set of serially controlled stepper motors in conjunction with various clutches and pulleys to move the string at a constant speed. Any questions on the \textit{WRK of Oklahoma} system should be directed to its creator, Dr. Richard Whitney (\href{mailto:whitney3451@att.net}{whitney3451@att.net})\par

    \subsection{Spray-Card Hardware}
    To process spray-cards, they must first be scanned with a flatbed scanner. It is recommended to use a dedicated scanner (not a combination printer/scanner) for the highest quality. A supported resolution of at least 1200 dpi is recommended for most applications. \textit{AccuPatt} can communicate with the scanner directly (MacOS Only) or images can be scanned externally using the software of your choice and uploaded to \textit{AccuPatt} for processing.

    \end{enumerate}

    \begin{enumerate}
        \item Download \textit{AccuPatt} from \href{https://github.com/gill14/AccuPatt/releases}{its GitHub repository here} (You just need the \textit{AccuPatt.dmg} file).
        \item Install \textit{AccuPatt} by opening the downloaded .dmg as a volume. Drag the \textit{AccuPatt} icon to the \textit{Applications} shortcut icon. Since this app isn't registered with Apple, you will need to right click on the app and choose \textit{Open}.     \subsubsection{Fluorescent Dye}
    \label{sec:settings_string_dye}
    The default dye for new series. The listed parameters associated with the dye are used for configuring and acquiring data from the spectrometer. Several pre-loaded dyes are included, but new dyes can be added via the \textbf{Define/Edit Dyes} button which opens an edit window (\autoref{fig:settings_dye_manager}).\par
    The dye parameters are as follows:
    \begin{itemize}
        \item \textbf{Excitation Wavelength (nm):} The target wavelength of the excitation light source (LED + Band-Pass filter). Changing this value will NOT automatically adjust the excitation source; the proper LED and Band-Pass filter must be physically installed. While excitation data is stored in the datafile, \textit{AccuPatt} only utilizes it as a reference point in the \textbf{Test Spectrometer} window.
        \item \textbf{Emission Wavelength (nm):} The target wavelength of light emitted by the dye when excited. This is the wavelength at which intensity is captured as the relative dye deposition.
        \item \textbf{Integration Time (ms):} Time to collect light for a spectrometer reading. Think of this as the exposure on a camera; longer times correspond with more detail incorporated in each data frame, but a lower quantity of data frames per unit length of string.
        \item \textbf{Boxcar Width (nm):} The cross-spectrum wavelength width to average for each spectrometer reading. A value of 0 means to take a reading only from the spectrometer pixel nearest the target emission wavelength. A value of 5, for example, would have each spectrometer reading be an average of every pixel within 5 nm (+/-2.5 nm) of the target emission wavelength.
    \end{itemize}

    \subsubsection{Pattern Processing}
    \label{sec:settings_string_process}
    The default smoothing and centering applied to new series; both for individual passes and the average pattern. These settings can be adjusted on a per-pass or per-series basis from the \textbf{String Analysis} tab as well.
    \begin{itemize}
        \item \textbf{Smooth Window:} X-domain based distance over which the sliding smoothing filter is fit and applied
        \item \textbf{Smooth Order:} Polynomial order for smoothing filter
        \item \textbf{Center Method:} The pattern is horizontally shifted so either the centroid or center of distribution is the new zero. (These are equivalent for evenly spaced data, so it typically doesn't matter for regularly spaced string data)
    \end{itemize}

    \subsubsection{Plot Options}
    \label{sec:settings_string_plot}
    The visual-only settings for string plots; these are not saved with datafiles and do not affect computations of CV.
    \begin{itemize}
        \item \textbf{Intensity Units:} The y-axis units for emission data intensity. These are always stored in Absolute Units (AU) but may optionally be displayed as a Relative (\%) of the spectrometer's 16-bit saturation value (65535 AU).
        \item \textbf{Average Overlay:} The dashed line optionally displayed as an overlay to the average pattern as one of:
        \begin{itemize}
            \item \textbf{Inner-Swath-Half-Average:} Computes one-half the average y-value within the \textbf{Adjusted Swath Width} range and draws a horizontal line at that value bounded by vertical lines at the bounds of the \textbf{Adjusted Swath Width}. This is sometimes referred to as the "old-school" way of determining effective swath width, where the intersection points of the horizontal and vertical lines should approximately touch the plotted pattern.
            \item \textbf{Average:} Computes the average y-value of the entire pattern and draws a horizontal line at that value.
        \end{itemize}
        \item \textbf{Simulation View:} Set the x-bounds of the overlap simulation plots as one of:
        \begin{itemize}
            \item \textbf{One Swath Width:} Only the mathematically relevant portion of the simulated overlap will be shown, specifically datapoints between -swathwidth/2 and swathwidth/2.
            \item \textbf{All Swaths:} All selected simulated adjacent passes will be shown. Can be useful for illustrating the big picture of in-field overlap.
        \end{itemize}
    \end{itemize}

    \subsubsection{String Drive}
    The settings for controlling the stepper motors in capturing string data; not saved to the datafile.
    \begin{itemize}
        \item \textbf{Serial Port:} Searches for and automatically connects to an FTDI device if found. A refresh button allows a manual connection attempt. A colored status readout shows green if the device is ready and yellow if it is not.
        \item \textbf{String Length:} The length and units (ft or m) of string to process for a single pass.
        \item \textbf{String Speed:} The calibrated velocity of the string as it is processed. This is used to determine the location of each data point and duration of data capture for each pass. A \textbf{Calibrate} button opens an interactive calibration window (\autoref{fig:string_drive_speed}) to use a known length of string (defaults to flightline length but any length may be used) to calculate the speed.
        \item \textbf{Collect From:} The orientation Left to Right or Right to Left in which the data should be collected. This is typically Left to Right (unwinding string spools previously collected in the field) but should be set as Right to Left if processing string directly in the field from the aircraft's right side.
        \item \textbf{Manual Drive:} Buttons to activate the forward or reverse motors for testing or ad-hoc needs.
        \item \textbf{Command:} Facilitates direct querying and setting string drive stepper motor parameters to onboard nonvolatile memory. The Take-Up Reel corresponds to address \textbf{A} and the Supply Reel corresponds to address \textbf{B}. With a command typed into the text field, clicking the \textbf{Send} button will append a carriage return, encode the message and send it to the stepper motor driver. A string of return text is normally received, and is displayed when available. This return text may simply be an echo of your command, or it may contain parameter information. See the stepper motor driver documentation by clicking the \textbf{Open Stepper Manual} button for specific commands.
    \end{itemize}

    \subsubsection{Image Acquisition}
    \label{sec:settings_card_image_acquisition}
    \textit{These settings are persistent but are not saved to the datafile since they do not affect the processing of the spray card data itself.}\par
    Acquiring spray card images to save to the datafile can be done via uploading externally scanned images or through direct scanning in \textit{AccuPatt} (MacOS Only).
    \begin{itemize}
        \item \textbf{Load Method:} If scanned externally, select the method to load these images into \textit{AccuPatt} as either:
        \begin{itemize}
            \item \textbf{One Card per File:} Each card is externally scanned and saved as a separate image file. When loading, the user will be prompted to select each individual image file for each card. No flipping, cropping or other image manipulations will be performed.
            \item \textbf{Multiple Cards per File:} Multiple cards are externally scanned together in a single image file. When loading, the user will be prompted to select the single image file. The user will then be able to crop each card from the image, with initial automatic selection determined by:
            \begin{itemize}
                \item \textbf{Flip:} Whether to flip the image horizontally and/or vertically as the first step of automatic selection. This accommodates the various image orientations returned by different scanners and scanning software.
                \item \textbf{Card Order:} The order in which cards are arranged in the image file, which determines the initial automatic selection of each card. For example, if there are 4 cards scanned together in a 2x2 grid, and the order is set to \textit{Increasing} and \textit{Horizontal}, then the initial automatic selection for card 1 will be the top left quadrant of the image, card 2 will be the top right quadrant, card 3 will be the bottom left quadrant and card 4 will be the bottom right quadrant.
                \item \textbf{Card Crop:} The percentage of the automatically detected card width and height to crop. While it is best to capture as much of the card as possible, there are sometimes edge defects or slight misalignments in card placement that make it more practicable to set the crop to a value less than 100\%.
            \end{itemize}
            \item \textbf{From ZIP:} Multiple cards are externally scanned and saved individually into a ZIP archive file. When loading, the user will be prompted to select the ZIP file. Each card image will be extracted and loaded into \textit{AccuPatt} without any flipping, cropping or other image manipulations. This option is targeted primarily for use with Swath Gobbler\textsuperscript{TM} data sets, which are provided in this format.
        \end{itemize}
    \end{itemize}

    \subsubsection{Thresholding}
    \label{sec:settings_card_threshold}
    \textit{These settings are persistent but apply only to new cards; \textit{Defined Sets} have their own threshold settings on a per-card basis. Moreover, every individual card has its own threshold method and values which will override these default settings for that card. These settings are saved to the datafile on a per-card basis.}\par
    Scanned/Loaded card images must be converted to a binary format to distinguish stain pixels from background pixels. Thresholds are set to make this determination for each pixel of the image. \textit{AccuPatt} provides two threshold methods as follows:
    \begin{itemize}
        \item \textbf{Grayscale:} The image is converted to 8-bit grayscale (0-255 where 0 is white and 255 is black)and a threshold is set based on pixel intensity. This is the more traditional method for processing spray cards, and is typically more effective for cards with darker stains such as WSP.
        \begin{itemize}
            \item \textbf{Value:} The minimum intensity value for a pixel to be considered a stain pixel. This is typically set based on the intensity histogram of the image, where the goal is to set the threshold at a value that effectively distinguishes the stain pixels from the background pixels.
            \item \textbf{Method:} The method for determining the threshold value. The \textbf{Manual} method uses the user-defined value as the threshold. The \textbf{Auto} method uses an algorithm (Otsu's Method) to automatically determine the optimal threshold value based on the intensity histogram of the image. 
        \end{itemize}
        \item \textbf{HSB:} The image is converted to Hue, Saturation and Brightness (HSB) color space and a threshold is set based on the Hue, Saturation and Brightness values (8-bit, 0-255) of each pixel. This method can be more effective for cards with lighter stains such as Cast-Coat, where the Hue and Saturation values can be more effective at distinguishing stains from the background than pixel intensity alone. Minimum and Maximum bands can be set for each of the three HSB parameters. If \textbf{Pass} is selected for the parameter, a pixel must fall within the defined range for that parameter to be considered a stain pixel (i.e. a band-pass filter is set); if \textbf{Pass} is NOT selected, a pixel must fall outside the defined range for that parameter to be considered a stain pixel (i.e. a band-reject filter is set). Note that all three parameters are applied simultaneously, so a pixel must meet the criteria for all three parameters to be considered a stain pixel.
    \end{itemize}

    \subsubsection{Stain Processing}
    \label{sec:settings_card_stain}
    \textit{These settings are persistent but apply only to new cards; \textit{Defined Sets} have their own stain processing settings on a per-card basis. Moreover, every individual card has its own stain processing settings which will override these default settings for that card. These settings are saved to the datafile on a per-card basis.}\par
    Once a card image is thresholded to a binary format, the resulting stain pixels are processed to determine the location and size of each individual stain. This is done through a connected components analysis, where adjacent stain pixels are grouped together into individual stains. The parameters for this process are as follows:
    \begin{itemize}
        \item \textbf{Watershed:} Whether to apply a watershed algorithm to separate adjacent stains that may be touching or slightly overlapping. \textit{AccuPatt} uses a marker-controlled watershed algorithm, where the distance transform of the binary image is used to identify the centers of stains as markers, and the watershed algorithm is applied to the distance transform to separate adjacent stains. \textit{It is generally NOT recommended to utilize the watershed algorithm for pattern testing data, as it can introduce more errors than it resolves. Visual verification (via the Outline image where stain borders are drawn on the original image) should always be performed if this option is used.}
        \item \textbf{Min Area:} The minimum area (in pixels) for a group of connected stain pixels to be considered a valid stain. This is typically set to exclude small specks of noise that may be misidentified as stains.
        \item \textbf{Approximation:} Whether to apply a contour approximation algorithm to the detected stains. This will alter stain size and should be used with caution. There approximation methods are as follows:
        \begin{itemize}
            \item \textbf{None:} No contour approximation is applied; the stain size is determined solely by the number of connected stain pixels.
            \item \textbf{Enclosing Circle:} The stain is approximated as a circle, where the radius of the circle is determined by the distance from the center of the stain to the farthest connected stain pixel. This method can be effective for stains that are roughly circular in shape, but can overestimate the size of irregularly shaped stains.
            \item \textbf{Fit Ellipse:} The stain is approximated as an ellipse, where the major and minor axes of the ellipse are determined by fitting an ellipse to the connected stain pixels. This method can be effective for stains that are elliptical in shape, but can also overestimate the size of irregularly shaped stains.
            \item \textbf{Convex Hull:} The stain is approximated as a convex hull, which is the smallest convex shape that can enclose all of the connected stain pixels. This method can be effective for stains of all shapes, but can overestimate the size of stains with concave features.
        \end{itemize}
        \item \textbf{Max Count:} The maximum number of stains to be detected on a single card. If the number of detected stains exceeds this value, \textit{AccuPatt} will cease processing the image. This is essentially a computational fail-safe for improperly thresholded images that are returning an excessive number of stains, which can cause the application to freeze or crash.
    \end{itemize}

    \subsubsection{Spread Factor}
    \label{sec:settings_card_spread}
    \textit{These settings are persistent but apply only to new cards; \textit{Defined Sets} have their own spread factor settings on a per-card basis. Moreover, every individual card has its own spread factor settings which will override these default settings for that card. These settings are saved to the datafile on a per-card basis.}\par
    Determination of originating droplet size from stain size is not straightforward, as the stain size is a function of both the droplet size and the spread factor, which is influenced by various factors such as spray solution properties, humidity, and paper properties. However, if a spread factor can be determined for the specific conditions of the pattern testing, it can be applied to the stain size to provide an estimate of droplet size.\par
    \textit{AccuPatt} provides a simplistic approach based upon longstanding industry practice wherein the stain diameter ($D_S$) is determined from a circle of equal projection area of the stain and the originating droplet diameter ($D_D$) is determined via one of the following equations:
    \begin{itemize}
        \item \textbf{None:} $D_D = D_S$
        \item \textbf{Adaptive:} $D_D = D_S / (aD_S^2+bD_S+cD_S)$
        \item \textbf{Direct:} $D_D = aD_S^2+bD_S+cD_S$
        \item \textbf{Logarithmic:} $D_D = a\ln(D_S)+bD_S+c$
    \end{itemize}
    Where $a$, $b$ and $c$ are user-defined coefficients. The \textbf{Adaptive} method is the most commonly used, where the stain diameter is divided by the spread factor to determine droplet diameter; for context, this was the method used by \textit{DropletScan}. The \textbf{Direct} method has previous documented use in \textit{DepositScan}. The \textbf{Logarithmic} method is used in \textit{DropFlight}. The coefficients for the various methods can be found in the associated application's literature or can be determined experimentally for the specific conditions of the pattern testing.\par
    It is important to note that these equations are simplifications and may not accurately capture the complex relationship between droplet size, stain size and spread factor under all conditions. Therefore, any estimates of droplet size derived from stain size should be interpreted with caution and an understanding of the limitations of this approach.

    \subsubsection{Defined Sets}
    \label{sec:settings_card_defined_sets}
    \textit{Defined Sets are persistent.}\par
    These are user-defined sets of spray cards, including (for each card) the name, location, threshold settings, stain processing settings and spread factor settings. These are intended to facilitate the processing of pattern testing data by allowing users to save and apply specific settings for different types of cards or testing conditions. For example, a user may have one defined set for processing 9 WSP cards at 8 foot spacing (traditional pattern testing alongside string) with specific threshold, stain processing and spread factor settings, and another defined set for processing 75 Cast-Coat cards at 2 foot spacing with different settings.\par

    \subsubsection{Pattern Processing}
    \label{sec:settings_card_pattern}
    \textit{The settings are persistent and apply to new spray card Passes and Series, but can be overridden on a per-Pass or per-Series basis. Only Center Method is saved to the datafile.}\par
    These settings affect the processing of spray card data for Pass patterns, Series average pattern and CV calculations. The parameters are as follows:
    \begin{itemize}
        \item \textbf{Y-Axis:} The y-axis units for all spray card plots and the basis for swath/uniformity calculations. Available options are:
        \begin{itemize}
            \item \textbf{Coverage:} The percent of the card area covered by stain pixels. This calculation is independent of the spread factor and is therefore the most direct measure of the pattern as captured on the card itself.
            \item \textbf{Deposition:} The calculated volume per unit area of spray solution deposited on the card, which is derived from the stain size and spread factor. This calculation is dependent on the spread factor and is therefore a more indirect measure of the pattern, but it can be more informative for understanding droplet size distribution and potential efficacy of the application. The units will be either gal/acre or l/ha depending on the Rate Units selected in Series Observables Settings.
            \item \textbf{Drops per $cm^2$:} The number of detected stains per unit area of the card. This calculation is independent of the spread factor and is therefore a direct measure of the droplet density on the card, but it does not account for the size of the stains or droplets.
            \item \textbf{Drops per $in^2$:} The number of detected stains per unit area of the card. This calculation is independent of the spread factor and is therefore a direct measure of the droplet density on the card, but it does not account for the size of the stains or droplets.
        \end{itemize}
        \item \textbf{Center Method:} The method for determining the center of the pattern, which is used as the reference point to horizontally shift (center) a Pass pattern and Series average pattern for swath and uniformity calculations. The options are:
        \begin{itemize}
            \item \textbf{Centroid:} The x value (location) of the geometric center of the pattern. This is equivalent to the center of distribution (mass) if the space between all cards is uniform.
            \item \textbf{Center of Distribution:} The x value (location) where the pattern is balanced on either side via weighted averaging. This is useful for patterns where the space between cards is not uniform, as it accounts for the varying distances between cards in determining the center of the pattern.
        \end{itemize}
    \end{itemize}

    \subsubsection{Plot Options}
    \label{sec:settings_card_plot}
    \textit{These settings are persistent but are not saved to the datafile since they do not affect computations of CV.}\par

            \item \textbf{All Swaths:} All selected simulated adjacent passes will be shown. Can be useful for illustrating the big picture of in-field overlap.

    \subsubsection{Automated Pattern Isolation \& Denoising}
    \label{sec:string_denoising}
    After trimming edge anomalies, it is necessary to raise the \textbf{Floor} of the pattern to exclude data subjectively perceived to be blank string. This step is critical to ensuring that this background noise is not included in the patterns used for interpretation and uniformity calculations. This is really no different to adjusting physical filters on the fluorometers of the bad-old days, except that this step is now software post-processing instead of hardware pre-processing.\par
    To counter the subjective nature of this step and combat its inadvertent omission by less-experienced users, \textit{AccuPatt} automatically sets the initial \textbf{Floor} to a Signal-to-Noise Ratio (SNR) of 3. Because every pattern is different and the algorithm isn't perfect, the \textbf{Floor} may still be adjusted freely after it is initially set.\par
    
    \paragraph{Identifying a Segment of Blank String}
    The lowest contiguous 5\% of raw pattern data (after excluding data outside the \textbf{Trim L} and \textbf{Trim R} bounds) is found and used as a representation of blank string. This is graphically represented to the user by highlighting that segment of data points in red. \textit{Note: This depends upon and assumes the string actually having a segment of string without dye deposit; if this is not the case, do not rely upon this algorithm.}

    \paragraph{Compute the Baseline}
    The baseline for SNR is the y-value to which all data points will be compared to.
    \begin{equation}
        {SNR}_{base}=\bar{y}
    \end{equation}
    where:\\
    \begin{tabular}{r l}
        $\bar{y}$  & is the mean value of the data points in the blank string segment.
    \end{tabular}

    \paragraph{Compute the Noise of Blank String}
    We can determine the noise as the standard deviation of the blank string data by:
    \begin{equation}
        N_{RMS}=\sqrt{\frac{\sum_{i=1}^{n}(y_i-\bar{y})^2}{n-1}}
    \end{equation}
    where:\\
    \begin{tabular}{r l}
        $y_i$   & are the individual data points in the blank string segment, and\\
        $n$  & is the number of data points in the blank string segment.
    \end{tabular}

    \paragraph{Set the Floor to a SNR=3}
    The SNR is computed as:
    \begin{equation}
        SNR=\frac{Y-{SNR}_{base}}{N_{RMS}}
    \end{equation}
    where:\\
    \begin{tabular}{r l}
        $Y$ & is any given y-value.\\
    \end{tabular}\par
    So, using an SNR=3, the floor is computed as:
    \begin{equation}
        Floor=3N_{RMS}+{SNR}_{base}
    \end{equation}

    \subsubsection{Assessing Quality of Pattern Data}
    Before a pattern is interpreted, its data should be assessed for quality. Specifically, the goal should be to have reasonable certainty that the deposited pattern has been isolated from the noise of blank string. Below are some examples of what to look for. The main takeaway is to question the validity of the data before you question the shape/width of the resultant pattern.

    \paragraph{Good Isolation}
    A pattern with good isolation from blank string is easy to spot (\autoref{fig:string_snr_good}). The segments of blank string are visible as fairly flat compared to the pattern with the vertical scale of the plot squeezing the vertical variation in the blank string segments to appear as barely perceptible. Note also that a majority of the pattern is in the green zone ($SNR\ge 10$), meaning that the pattern signal is very clearly differentiated from the variation in blank string noise.

    \begin{figure}[H]
        \centering
        \makebox[\textwidth]{\includegraphics[width=\textwidth]{string_snr_good.png}}
        \caption{String Analysis - Quality of Pattern Data - Good Isolation}
        \label{fig:string_snr_good}
    \end{figure}

    \paragraph{Marginal Isolation}
    A pattern with marginal isolation from blank string can be difficult to spot (\autoref{fig:string_snr_marginal}). The segments of blank string are somewhat visible, but are not quite visibly differentiable from the pattern; in other words it is difficult to visibly determine the point at which the pattern begins on at least one side (left or right). The vertical variation in what \textit{AccuPatt} has determined to be the blank segment is very perceptible. Note also that a majority of the pattern is in the yellow zone ($3\le SNR<10$), meaning that there is mild uncertainty that the pattern is isolated from the blank string segment.\par
    The reasons for marginal isolation are myriad and include, but are not limited to:
    \begin{itemize}
        \item Insufficient dye loading
        \item Degraded or improperly mixed dye
        \item Testing exceedingly large droplet spectra, such as AccuFlo nozzles where the string collection efficiency is low.
        \item Insufficient sampling width; if dye actually deposits onto the entire extent of the string, there is no blank string to reference from.
    \end{itemize}
    In the case of the provided example in \autoref{fig:string_snr_marginal}, it was determined that there actually was deposition across the entire extent of the string. This determination was made based on an observed $SNR_{base}\approxeq7400$ for other passes in the same series. Thus, in this case, the noise isolation algorithm's suggested \textbf{Floor} was not appropriate and could have been overrode. However, because the pattern could not be isolated it was excluded from analysis.

    \begin{figure}[H]
        \centering
        \makebox[\textwidth]{\includegraphics[width=\textwidth]{string_snr_marginal.png}}
        \caption{String Analysis - Quality of Pattern Data - Marginal Isolation}
        \label{fig:string_snr_marginal}
    \end{figure}

    \paragraph{Insufficient Isolation}
    A pattern with insufficient isolation will have little to no visually distinguishable transition point between itself and blank string (\autoref{fig:string_snr_bad}). The majority of the string's extent will have similar vertical variation and will appear exaggerated due to the scaling of the plot in absence of a pattern rising out from it. Note that a majority of the data points do not even survive the $SNR\ge 3$ \textbf{Floor}.\par
    It may seem obvious, but these "patterns" can and have been interpreted as actual deposition by experienced folks who simply failed to question the data.\par
    The reasons for insufficient resolution are typically:
    \begin{itemize}
        \item No dye loading
        \item Incorrect or severely degraded dye
        \item Incorrect excitation light source and filter
        \item Incorrect target emission wavelength or integration time set (see \autoref{sec:settings_string_dye})
    \end{itemize}

        \caption{String Analysis - Quality of Pattern Data - No Isolation}
        \label{fig:string_snr_bad}
    \end{figure}

    \subsection{Pattern Processing Options}

    \textbf{Series Options} can apply to all passes and/or the average pattern:
    \begin{itemize}
        \item \textbf{Smooth Average:} Apply smoothing filter to average pattern. Checked by default.
        \item \textbf{Align Center Average:} Shift average pattern horizontally using chosen center method. Checked by default.
        \item \textbf{Equalize Integrals:} Scale each pass to the same integrated area. Checked by default.
        \item \textbf{Advanced Options:} Opens a popup with the following options (defaults as set in Settings/String (\autoref{sec:settings_string_process})):
        \begin{itemize}
            \item \textbf{Smoothing Window:} X-domain based distance over which the sliding smoothing filter is fit and applied
            \item \textbf{Smoothing Order:} Polynomial order for smoothing filter
            \item \textbf{Center Method:} Choose whether to center the pattern with the centroid or Center of Distribution.
        \end{itemize}

    \subsection{Simulations Tab}
    The \textbf{Simulations} sub-tab contains two plots (\autoref{fig:card_simulations}). Both plots simulate additively overlapping the measured pattern at intervals of the adjusted swath width. The bold black line represents the resultant summed pattern, and is interpreted here as projected in-field uniformity. The dashed horizontal line represents the mean value, about which standard deviations are computed for coefficient of variation (CV) calculations. In other words, the further a data point on the bold black line is (vertically) from the dashed line, the more it contributes to the CV.
    \begin{itemize}
        \item \textbf{Racetrack:} [Upper Plot] Each simulated pass is plotted going the same direction (into the screen/paper)
        \item \textbf{Back \& Forth:} [Lower Plot] Every odd simulated pass is mirrored about the center. \color{red} The back \& forth simulation will not accurately represent in-field uniformity if the base pattern is obtained in a crosswind. \color{black}
    \end{itemize}
    The number of simulated adjacent passes is determined automatically based on the adjusted swath width and pattern width. The plots will denote the number used when it exceeds the legend's available area.\par
    The visible x-value range of the plot windows can be set to show only the mathematically relevant range (single swath width) or all simulated passes (see \autoref{sec:settings_card_plot}).\par
    A table is included which calculates the CV for select swath widths near the set adjusted swath width.
